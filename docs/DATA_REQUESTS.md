# Запросы данных

Главное во всех запросах — **регулярность и стабильный формат**. Конкретный формат подстроим под то,
что источнику удобно выгружать: парсер пишется один раз.

## 1. Оператору связи

Запрос лучше направлять от заказчика (предприятия) в рамках договора на обслуживание сети.
Все данные — только по узлам частной сети предприятия.

### Приоритет A

1. **Таблица параметров сети (RND / база сайтов).** Для каждой соты: сайт, координаты, eNB ID, Cell ID, ECI,
   PCI, EARFCN DL/UL, полоса, TAC, модель антенны, высота подвеса, азимут, механический и электрический тилт,
   мощность. Обновлённая версия — при каждом изменении.
2. **CM-выгрузка ENM** (Bulk CM Export, XML или CSV): `ENodeBFunction`, `EUtranCellFDD`, `EUtranCellRelation`,
   `SectorCarrier`, параметры RET. Раз в сутки или неделю.
3. **KPI по сотам**, почасово (минимум — посуточно):
   - доступность соты;
   - RRC Setup SR, E-RAB Setup SR;
   - E-RAB Drop Rate;
   - Intra-frequency HO SR;
   - трафик DL / UL;
   - пропускная способность на пользователя DL / UL;
   - утилизация PRB DL / UL;
   - число RRC-соединений (среднее и максимальное);
   - уровень UL-помех (`pmRadioRecInterferencePwr`);
   - распределение CQI.

   Вариант лучше: сырые PM-файлы ENM (3GPP XML), тогда формулы KPI посчитаем сами.
   Уже получаем: почасовой отчёт KPI по сотам (Excel). Чтобы значения за неделю и по группам сот считались
   точно, нужны почасовые счётчики к нему: `pmRrcConnEstabAtt/Succ`, `pmErabEstabAttInit/SuccInit`,
   счётчики сбросов E-RAB, `pmHoPrep*`/`pmHoExe*`. Хэндоверы — по парам соседей (`EUtranCellRelation`):
   так видно, на какую соту срывается переход.
4. **Аварии** по нашим узлам (RAN, транспорт, S1): активные и история. Лучше всего — онлайн-пересылка на наш
   сервер (SNMP-трапы, e-mail или файл: как удобнее оператору). Минимум — ежедневная выгрузка.

### Приоритет B

5. **Драйв-тесты Nemo:** сырые логи `.nmf` (открытый текстовый формат), отчёты, маршруты, даты.
   Файлы `.nmfs` зашифрованы и читаются только в Nemo: попросите сохранить их как `.nmf`
   (Nemo Outdoor: без шифрования; Nemo Analyze: File → Export) или выгрузить CSV с временем, координатами,
   ECI/eNB ID, PCI, EARFCN, TAC, RSRP, RSRQ, SINR.
6. **Транспорт (Ericsson):** топология, аварии; для радиорелейных линий — уровень сигнала, модуляция, доступность.
7. **Ядро (Nokia):** статус S1 по каждому eNB, число подключённых абонентов и сессий по APN.
8. **Изменения на сети:** план работ, уведомления об изменении конфигурации, инциденты и заявки.

### Приоритет C (если согласуют)

9. Учётная запись ENM только на чтение, с доступом только к нашим узлам (CLI / ENM Scripting).
   Тогда выгрузки автоматизируем сами и не нагружаем инженеров оператора.

**Канал доставки:** SFTP по расписанию (оператор кладёт в нашу папку или мы забираем из его).
Минимум — e-mail с вложениями на выделенный ящик.

## 2. Маркшейдерской службе

- Актуальная цифровая модель рельефа (GeoTIFF, TIN, облако точек или DXF) и периодичность съёмки.
- Ортофотоплан (GeoTIFF).
- Система координат и параметры перехода к WGS-84.
- План развития горных работ на квартал и год — для планирования покрытия наперёд.
- Координаты мачт и сайтов, если ведутся.

## 3. Эксплуатации и диспетчерской

- Перечень техники с LTE-роутерами: модель роутера, IMEI, IP-адрес, наличие GPS, способ управления
  (веб-интерфейс, SNMP, облако производителя).
- Модели PTT-раций (работают ли на Android), используемая PTT-платформа.
- Диспетчерская система (АСУ ГТК): есть ли, какая, можно ли получать координаты техники.

## 4. ИТ и ИБ

- ВМ: ОС, ресурсы (ориентир в [ARCHITECTURE.md](ARCHITECTURE.md#8-развёртывание-и-поставка)), доступ для администрирования.
- Маршрут от абонентов LTE (APN) до ВМ, разрешённые порты (8883 или 443).
- Способ доставки обновлений: перенос архивов или внутренний registry.
- Канал уведомлений: почта, Telegram или другое.
- AD / LDAP для входа.
- Требования к персональным данным: треки перемещения сотрудников.

## 5. Образцы для разработки

- Экспорт лога NetMonitor.
- Текущие таблицы сайтов и сот (Excel в любом виде).
- Любой пример лога или отчёта Nemo, KPI-отчёта или выгрузки аварий от оператора, если что-то уже приходит.

При необходимости обезличить: для разработки важны структура и форматы, а не реальные идентификаторы.
