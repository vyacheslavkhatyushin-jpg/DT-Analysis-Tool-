# 0004. Статистика KPI оператора

Статус: принято, 2026-09.

## Контекст

Оператор присылает почасовой отчёт KPI по сотам (Excel, выгрузка из ENM/ENIQ). Отчёт снят с живой сети,
поэтому имена eNB и сот в нём актуальнее таблицы сайтов. В отчёте только проценты и объёмы, без счётчиков:
проценты за период или по группе сот из них точно не считаются. Состав столбцов со временем может меняться.

## Решение

- `kpi_cell` — сота в том виде, как её называет статистика. Связь с инвентарём — по совпадению имени или
  явная (`cell_id`), если имена разошлись. Несовпадения показываются в сверке. Там можно привязать соту
  и сразу переименовать соту инвентаря по статистике. История под прежним именем остаётся привязанной.
- `kpi_sample (kpi_cell_id, kpi, time, value)` — узкая гипертаблица TimescaleDB: новый показатель не требует
  миграции. Чанки по 30 дней, сжатие через 60 дней (сегменты `kpi_cell_id, kpi`).
- Загрузка потоком: строки отчёта идут через `COPY` во временную таблицу, затем upsert. Повторная загрузка
  того же часа заменяет значение. Время отчёта местное, часовой пояс указывается при загрузке.
- Каталог показателей в коде (`dtat.kpi.definitions`): единицы, пороги «внимание / проблема»,
  способ агрегации. Способ подобран по реальным данным так, чтобы значения за период ближе всего
  совпадали со значениями оператора, посчитанными им по счётчикам: для скорости, хэндоверов и CQI —
  среднее, взвешенное по трафику часа, для остальных — простое среднее, для объёмов — сумма.
- Кроме значения за период показывается худший час.

## Последствия

- Значения за период приблизительные. На данных за месяц они расходятся с цифрами оператора по eNB
  в среднем на 0,1–2 единицы: п. п. для процентов, Мбит/с для скорости. Проценты по всей сети
  из часовых значений не считаются: там ошибка доходит до нескольких раз.
- Точные значения дадут почасовые счётчики (pm*). Их можно хранить в той же таблице под своими кодами
  и считать KPI по формулам.
