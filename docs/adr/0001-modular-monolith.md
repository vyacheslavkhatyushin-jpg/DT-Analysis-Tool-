# 0001. Модульный монолит и одна база PostgreSQL

Статус: принято, 2026-09.

## Контекст

Разрабатывают два человека; система разворачивается на одной ВМ в закрытой сети; нагрузка небольшая
(десятки сайтов, сотни устройств, до миллиона замеров в сутки на следующих этапах).

## Решение

- Один backend-процесс на Python (FastAPI), разделённый на модули (`auth`, `inventory`, `audit`, `maps`, далее
  `measurements`, `monitoring`, `planning`). Модули общаются через сервисные функции, а не по сети.
- Одна база: PostgreSQL 16 с PostGIS (геометрия), TimescaleDB (временные ряды замеров и KPI) и h3 (бинирование).
- Синхронный SQLAlchemy 2 + psycopg 3: проще, а RF-расчёты и парсинг файлов всё равно CPU-bound.

## Последствия

- Минимум компонентов для эксплуатации и бэкапа: один дамп БД содержит всё.
- При росте нагрузки тяжёлые задачи (парсинг, расчёт покрытия) выносятся в отдельный процесс-воркер на том же коде.
