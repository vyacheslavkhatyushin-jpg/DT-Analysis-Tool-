# 0002. История инвентаря

Статус: принято, 2026-09.

## Контекст

Замеры (драйв-тесты, телеметрия) нужно привязывать к конфигурации сети **на момент измерения**:
оператор меняет тилты и PCI, передвижные мачты переезжают за фронтом работ.

## Решение

- `cell_version`: снимок радиопараметров соты с периодом действия `tstzrange`. Новая версия создаётся только
  при изменении параметров, влияющих на радио (PCI, EARFCN, азимут, тилты, высота, мощность, статус, ECI).
- `site_position`: история координат сайта.
- Пересечение периодов запрещено exclusion-ограничением (`btree_gist`) на уровне БД.
- Первая версия действует «с начала времён»: к ней привязываются и замеры, сделанные до заведения объекта.
- Изменение можно датировать задним числом (`effective_at`), но не раньше предыдущего изменения и не в будущем.
- Отдельно `change_log`: кто, когда, через что (интерфейс, импорт, система) и какие поля поменял.

## Последствия

- Запрос «конфигурация соты на момент T»: `valid_period @> T` по индексу.
- Нельзя вставить изменение между двумя существующими версиями; для исправления истории понадобится
  отдельный административный инструмент.
