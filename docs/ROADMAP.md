# Роадмап

Порядок определяется зависимостями: сначала то, что не требует ничего от оператора, затем подключение его данных.
Каждый этап даёт результат, которым можно пользоваться. Данные оператора подключаем, как только они появятся,
не дожидаясь очереди этапа 5.

## Этап 0. Вводные (сразу, параллельно с этапом 1)

- Отправить запросы из [DATA_REQUESTS.md](DATA_REQUESTS.md) оператору, маркшейдерии, эксплуатации, ИТ/ИБ.
- Собрать образцы файлов для парсеров: лог NetMonitor, текущие таблицы сайтов, любые отчёты оператора.
- Уточнить модели LTE-роутеров и раций, путь данных APN → ВМ, ОС ВМ.

**Результат:** известны источники и форматы, есть образцы.

## Этап 1. Фундамент, инвентарь, карта

Статус: реализовано, ждёт установки на ВМ и реальных данных.

- [x] Монорепо, CI, Docker Compose, миграции БД, локальные учётки и роли.
- [x] Генератор синтетического карьера для разработки и демо.
- [x] Инвентарь: сайты с историей перемещений, eNB, соты с версиями конфигурации, устройства, техника;
  журнал изменений; импорт и экспорт Excel по шаблону.
- [x] Карта: офлайн-подложки PMTiles (OSM, ортофото), слои GeoJSON (контур карьера, отвалы), сайты,
  секторы по азимуту, карточки объектов, поиск.
- [x] Офлайн-поставка: архив релиза, `install.sh`, HTTPS, бэкап и восстановление.
- [ ] Установка на ВМ предприятия.
- [ ] Реальные данные: сайты и соты (Excel или выгрузка оператора), ортофото и контур карьера от маркшейдерии.

**Готово, когда:** система развёрнута на ВМ, все сайты и соты заведены, карта работает без интернета.

## Этап 2. Анализ драйв-тестов (импорт)

- Парсеры: NetMonitor, Nemo (`.nmf`), CSV общего формата.
- Сессия: трек, раскраска по RSRP / RSRQ / SINR / обслуживающей соте, линии «точка → сота», события смены
  соты, графики по времени, синхронный курсор «карта ↔ графики».
- Статистика по сотам и сессии, CDF, пороги качества; бинирование H3; сравнение двух сессий («до / после»).
- Автопоиск проблем: слабое покрытие; помехи (RSRP в норме, SINR плохой); перекрытие (много сильных соседей);
  обслуживание дальней сотой (overshooting).
- Экспорт отчёта (Excel / PDF).

**Готово, когда:** логи NetMonitor и квартальный драйв Nemo разбираются в одном интерфейсе.

## Этап 3. Своё приложение и онлайн-драйв

- Android: сбор радио-параметров и GNSS, режим драйв-теста (1 Гц) со сценариями ping / iperf3 / HTTP,
  офлайн-буфер с досылкой, экспорт лога.
- Сервер: приём по MQTT, live-карта в браузере, серверная часть тестов (iperf3 и цель для ping на ВМ).

**Готово, когда:** во время объезда карьера трек и качество видны в браузере в реальном времени,
а при потере связи данные не теряются.

## Этап 4. Постоянный мониторинг со стороны абонента

- Приложение в режиме фонового агента на смартфонах и рациях (если рации на Android).
- Телеметрия LTE-роутеров техники (способ зависит от модели).
- Стационарные зонды в ключевых точках с периодическими синтетическими тестами.
- Накопительная карта покрытия по H3 за период, карта проблемных зон, динамика.
- Алерты: зонд недоступен; деградация зоны; сота пропала из наблюдений (косвенный признак аварии без доступа к FM).
- Уведомления.

**Готово, когда:** система сама обнаруживает проблемы связи без данных оператора и показывает их на карте.

## Этап 5. Данные оператора

Начат раньше очереди: почасовой отчёт KPI от оператора уже приходит.

- [x] KPI: загрузка почасового отчёта по сотам, сверка имён с инвентарём, страница «KPI сети»
  с проблемами по показателям, раскраска карты по KPI, графики в карточке соты ([ADR 0004](adr/0004-kpi-statistics.md)).
- [ ] KPI по счётчикам (pm*): точные значения за период и по группам сот; хэндоверы по парам соседей.
- [ ] Автоматические находки и выгрузка отчёта для оператора.
- CM: импорт, сверка с инвентарём, журнал изменений, внесённых оператором.
- Аварии: журнал, привязка к сайтам и сотам, уведомления.
- Корреляция: проблемная зона ↔ KPI и аварии обслуживающих сот.

**Готово, когда:** по любой проблемной зоне видны и абонентская, и сетевая стороны.
Сроки зависят от договорённостей этапа 0.

## Этап 6. Планирование

- Загрузка DEM маркшейдерии с версиями, профиль трассы, расчёт покрытия (LoS + дифракция), калибровка по накопленным замерам.
- What-if: новая точка, перенос мачты, смена высоты, азимута, тилта; покрытие по плану горных работ.
- Проверки: PCI (коллизии, конфузии, mod 3 / mod 30), соседства по фактическим измерениям.
- Отчёты для обоснования изменений перед оператором.

**Готово, когда:** откалиброванный прогноз совпадает с замерами в пределах заданной погрешности
(проверяется на отложенной выборке замеров).

## Бэклог

- Заявки и работы по обслуживанию, документы и фото по сайтам.
- Отчёты по SLA для заказчика.
- Качество PTT: время установления вызова, задержка голоса.
- Интеграция с диспетчерской системой (АСУ ГТК), если она есть.
- Вход через AD / LDAP.
